# Підключення спільного сховища ДКВС

`index.html` використовує Supabase Auth для входу та таблиці `dkvs_profiles` і `dkvs_records` для спільних записів. Publishable key у браузерному коді є публічним; доступ обмежують RLS-політики з `supabase-schema.sql`.

## Після першого запуску схеми

1. Запускайте актуальний `supabase-schema.sql` у Supabase → SQL Editor після кожної зміни схеми. Він додає потрібні політики доступу, процедуру видачі ролі заступника лідером, повторну реєстрацію вимкнених акаунтів і приватне сховище відеодоказів.
2. У Supabase відкрийте Authentication → Providers → Email і вимкніть підтвердження email. Сайт приймає ім’я та пароль, а не адресу пошти, тому Auth отримує внутрішню технічну адресу на домені `example.com`.
3. Відкрийте сайт, виберіть «Створити акаунт» і зареєструйте `Дмитро Яворський` з потрібним паролем та ігровим ID.
4. У SQL Editor виконайте команду призначення власника з кінця `supabase-schema.sql` (за потреби впишіть точне ім’я входу). Після цього Дмитро зможе призначати ролі через сайт.
5. Розмістіть разом усі файли з папки `outputs`, включно з `supabase.js` і `supabase-schema.sql`.

Усі акаунти, створені через форму, отримують роль «Співробітник». Лідер може призначити іншого активного працівника заступником; власник може призначати всі ролі. Тільки лідер, заступник, слідкуючий або власник можуть створювати оголошення. Ці права також перевіряються базою даних, а не лише інтерфейсом. Видалення акаунта вимикає профіль; після цього людина може зареєструватися з тим самим ім’ям знову, а новий профіль починає з ролі «Співробітник».

Відео чорного списку завантажуються в приватний Storage bucket. Інші прикріплені зображення залишаються в записах як дані зображень.
